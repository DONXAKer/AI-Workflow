# AI-Workflow Tasks

Все задачи на разработку живут здесь как `.md` файлы.

## Структура

```
tasks/
├── TEMPLATE.md     — шаблон для новой задачи
├── README.md       — этот файл
├── active/         — задачи в работе И запланированные (roadmap)
└── done/           — завершённые задачи
```

`active/` — это **и workbench, и roadmap**. Любая идея, до которой мы планируем дойти, заводится здесь. Статус «в работе» vs «когда-нибудь» различается через поле `status:` в frontmatter:

| `status:` | Что значит |
|-----------|------------|
| `planned` | Запланировано, ещё не стартовало |
| `in_progress` | Сейчас в работе |
| `blocked` | Заблокировано (зависимость, внешний ресурс, требует решения) |
| `done` | Заполняется автоматически при переводе в `done/` |

## Workflow

1. Создать новый файл в `active/` из `TEMPLATE.md`:
   ```
   cp tasks/TEMPLATE.md tasks/active/FEAT-CORE-002-описание.md
   ```
2. Заполнить 4 обязательных раздела: **Как сейчас / Как надо / Вне scope / Критерии приёмки**. Frontmatter `status: planned`.
3. Когда задача стартует — `status: in_progress`.
4. После реализации:
   - Переместить в `done/`.
   - В `## Реализовано` указать конкретные артефакты (файлы, тесты, UI-страницы).
   - Все критерии приёмки помечаются `- [x]`.
   - `status: done` + `done_date: YYYY-MM-DD` в frontmatter.

## Naming convention

`<TYPE>-<AREA>-<NUMBER>-<slug>.md` (через дефис, единый стиль)

| Префикс | Значение |
|---------|----------|
| `FEAT-` | Новая функциональность |
| `FIX-`  | Багфикс |
| `REFACTOR-` | Рефакторинг без изменения поведения |
| `UI-` | Изменения UI без backend (legacy-префикс, для новых задач предпочтительнее `FEAT-UI-`) |

`AREA` — короткий ярлык подсистемы (`CORE`, `UI`, `DB`, `BLOCK`, `PIPELINE`, `RUNNER`, `INTEGRATION` и т.п.).

Номер — инкремент в пределах префикса+area.

## Правила заполнения

- **Все 4 раздела обязательны.** Пустой раздел → пайплайн остановится и попросит уточнения.
- **Критерии приёмки — observable**. Не «работает хорошо», а «`gradle build` зелёный» или «тест X проходит».
- **Вне scope** — главный защитный раздел. Пусто → scope creep почти гарантирован.
- **`## Реализовано` в `done/`** — список артефактов (см. TEMPLATE.md). Обязателен для всех done-задач.

## Существующий контент

В `done/` сейчас лежат файлы, созданные до унификации формата (могут не иметь frontmatter и `## Реализовано`). Это нормально — задним числом приводить их к новому формату не требуется. Все **новые** задачи следуют шаблону.
